# Making Simple reliable and simple

Reviewed and implemented on September 5, 2026. This is an audit of all five local apps and the shared launcher, with real application tests and the legacy Word and Excel files supplied by the user. Measurements below compare old and new Simple code on this computer; they are not speed comparisons with Adobe, Microsoft, or Google.

The subsequent [complex-file stress review](COMPLEX_FILE_REVIEW.md) covers newly created six-page documents, four-sheet workbooks, copied Books PDFs, images and video, including the additional fixes and final executable delivery.

The most useful changes remove surprises: show the original document accurately, keep the original save format, make numbers readable inside cells, avoid recompressing untouched photos, and let people combine files in an explicit order. Full Word/Excel/Acrobat compatibility remains a larger project.

## Changes delivered

| --- | --- | --- |
| Legacy Word opening | The linked file is a binary `.doc`. The old import extracted plain text and discarded layout, four tables, and an image. | A local LibreOffice conversion engine recovers structured content. Page view and unchanged print/PDF export use the engine's compatible page rendering. Editing has a separate view because the current editor does not support every Word feature. Independent comparison with Google Docs also identified remaining floating-table and styling differences in the conversion engine. |
| Word watermark pagination | A background image in the header reserved 720 pixels of body space and expanded the sample into five pages. | A pinned, reproducible WordCanvas adapter places anchored header images behind the body without consuming flow space. | Document fonts and printing | Installed Windows fonts were replaced unnecessarily; repeated print/export recomposed the same revision; failed printer callbacks could leave a job stuck. | Installed font faces are used for editor and export metrics. PDFs are cached by revision. Print submission has timeout/crash handling and does not automatically resubmit an uncertain job. |
| Saved date values | The conversion engine refreshed a legacy DATE field when merely viewing or printing the file. | Cached DATE/TIME results are locked in a temporary conversion copy, so opening the sample retains its saved date. | Spreadsheet printing and PDF | Reconstructed print layout could ignore saved scale and margins, expand short rows, truncate overflowing text, left-align formatted numbers, or omit merged-cell border edges. | Print and PDF export use saved page layout by default, with a clear switch for custom settings. | Word imports inside PDF | PDF's separate Word import path also discarded page layout through plain-text/HTML reconstruction. | Opening Word files, dropping bytes, and Add pages now use the same local conversion engine and cached date preservation. The picker includes legacy DOC files. |

| Combining files | Opening multiple file types required separate conversion and insertion steps. | **Combine files** in the shared launcher accepts PDFs, DOC/DOCX, XLS/XLSX/ODS, PNG, and JPEG. Source-file overwrite, invalid ranges, encrypted PDFs, and unsupported interactive forms are rejected. |
| Video frames | A seek could export the previous frame, timestamps could drift during encoding, and an older asynchronous open could replace the newest choice. | Copy/export/print wait for the selected frame to decode, keep the playhead unchanged, use the captured timestamp, and ignore stale opens. The Google Docs comparison is a separate reference from LibreOffice. Simple's unchanged document print raster matched the LibreOffice render pixel-for-pixel at 1200 pixels, but LibreOffice itself placed some floating tables differently from Google and lost table-header styling. Matching a conversion engine is not proof of Google Docs or Word parity. The Google-provided reference PDF is retained locally with the test inputs, outside the source files.

No physical printer jobs were submitted. Preview and generated-PDF tests establish layout and application behavior; actual driver, spooler, printer, duplex, and paper-tray behavior still need a small hardware test matrix.

Packaged GUI suites should run one at a time. One concurrent print/export run timed out while discovering a PDF window; the same case passed separately. Six subsequent parallel PDF launches created distinct targets and isolated profiles without process loss, so the discovery timeout's cause was not established. Occluded windows can also defer page painting. The launcher now honors explicitly requested test profiles and passes that profile to detached modes, keeping test sessions separate from a live workspace.

## Supplied Excel workbook

The shared spreadsheet is an original binary `schedule_template.xls`, not an XLSX file. Its original download matches the local fixture byte-for-byte. The audit compares the actual Google Sheets view, Google's exports, the original file's stored dimensions and print records, and an independent office-engine render. Read-only reference exports and local test copies leave the shared workbook unchanged.

The file has five main columns, a lower notes section, and merged signature boxes. Google Sheets displays its column widths consistently with Simple's existing grid. A deeper check found that many rows explicitly store a 16-point automatic height; the general importer had omitted those records and Simple had shown them at 15 points. The source also stores Arial 10 as its Normal font even though many visible cells override it with Arial 12. Normal-font metrics matter for interpreting Excel's character-based column widths in print.

At a 1440 × 900 window, Fit sheet selects 73% and shows the entire form. Fit data width selects 173% and keeps the last used column inside the viewport. The visual checks include complete outer borders and all three signature rectangles, without thickening shared cell edges. Edited sample amounts and formulas remain comfortably aligned inside the source's tight rows. Original-format Save/reopen checks retain the 16-point heights, Arial 10 Normal font, and 91% print scale.

The final edited test PDF is [available locally](../simple_calc_source/tmp/schedule-export.pdf), with [a full-page visual check](../simple_calc_source/tmp/schedule-export-page1.png). It contains test values entered into a local copy. The downloaded original and reference fixture retain SHA-256 `0b7c348b35dc5624ae134c09043708b85b980648c89bfda587522f4f9c0c8787`. Header pictures and some advanced workbook objects remain unsupported in the editable model; the app explains this before overwriting an edited legacy file and keeps its original backup.

Google's exported PDF divides this file into seven pages, while the source's saved 91% print scale and the office engine produce one Letter page. Google's export is therefore useful as a content reference but cannot be treated as the authoritative print layout. The office engine also renders an Excel header color token as visible zeros, so that output needs independent scrutiny too. This known limitation remains in native Office conversion used by Combine; Simple's own spreadsheet print renderer handles the color token correctly. Fidelity tests must verify the stored document settings and intended content, rather than blindly copying either converter's mistakes.

## What professional systems teach us

Microsoft separates Save from changing file format and documents feature losses during conversion. Simple should retain format and expose a clear alternative whenever it cannot preserve the source. [Microsoft: Save your workbook](https://support.microsoft.com/en-us/office/save-your-workbook-92e4aae0-452d-497f-a470-570610ff720a), [Microsoft: change file format](https://support.microsoft.com/en-us/excel/save-a-workbook-in-another-file-format).

Excel treats row height, column width, AutoFit, and alignment as document data. The rendering fix preserves those values and fits line boxes within the available cell space. [Microsoft: dimensions and AutoFit](https://support.microsoft.com/en-us/excel/change-the-column-width-and-row-height), [Microsoft XLS default row-height specification](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/407c7fd6-d378-4901-8c79-432bfe38cef9), [SheetJS: row properties](https://docs.sheetjs.com/docs/csf/features/rowprops/).

Excel column widths are defined using digit widths in the workbook's Normal style. Its print headers also contain formatting and page-field codes, not just literal text. Simple now measures the source Normal font for printing and interprets supported header/footer codes. [Microsoft: column width definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.column?view=openxml-3.0.1), [Microsoft: header and footer codes](https://learn.microsoft.com/en-us/office/vba/excel/concepts/workbooks-and-worksheets/formatting-and-vba-codes-for-headers-and-footers).

Acrobat's combine workflow puts arrangement before output. The new launcher follows this ordering and opens the finished result for review. [Adobe: combine files](https://helpx.adobe.com/acrobat/desktop/edit-documents/combine-files/combine-files.html), [Adobe: rearrange files](https://helpx.adobe.com/acrobat/desktop/edit-documents/combine-files/rearrange-combined-files.html).

PDF.js recommends rendering only visible pages to avoid excessive canvas memory. The same principle applies to editable image extraction: prepare what the user requests and bound cached data. [PDF.js FAQ](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions).

Acrobat offers an explicit Print as image workaround for problematic PDF content or drivers. Simple should add this as an optional recovery path, with ordinary printing remaining the first path. Electron reports print-submission success/failure but that does not establish that a sheet physically printed. [Adobe: Print as image](https://helpx.adobe.com/acrobat/kb/quick-fix-print-pdf-image.html), [Electron: webContents printing](https://www.electronjs.org/docs/latest/api/web-contents).

LibreOffice publishes documented conversion filters for Word and Excel formats. The engine runs locally with isolated temporary profiles and macros/automatic link updates disabled. It is a compatibility aid, not a guarantee of Microsoft Office pixel parity. [LibreOffice command-line parameters](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html), [conversion filters](https://help.libreoffice.org/latest/en-US/text/shared/guide/convertfilters.html).

Legacy date preservation uses the documented field result and lock flag on a conversion copy. It does not replace matching date strings or change unrelated fields. [Microsoft: DOC field structure](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/751b09bb-72f0-45ef-8e87-666dea68219f), [Microsoft: field-end flags](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/28ab752b-055a-4725-8797-159bba0d125c).

## Local office engine and portability

This computer has a private, administrative extraction of LibreOffice 26.2.6 at `%LOCALAPPDATA%\simple\office-runtime`. It does not register LibreOffice as the default app. The signed installer was verified against the official SHA-256:

`f9877032fd908beb9c0ddf06df4af5c2e85f419c42e14876c4cce5aae5fb2660`

The engine is separate from the portable executable and is never required: Simple does not fetch, set up or update it, and every format offered in a picker works without it (see the README's "Optional office engine"). When a normal LibreOffice installation, a companion `tools/libreoffice/program/soffice.exe` folder next to the executable, `SIMPLE_LIBREOFFICE_PATH` or the folder above is present, Simple uses it. `scripts/setup-office-runtime.ps1` remains a developer tool for test PCs only. First-time Office conversion can take several seconds; repeated document conversions and unchanged document PDFs are cached with bounded memory.
