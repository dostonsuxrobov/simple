# Simple Docs

Simple Docs is a local-first Windows editor for `.docx` and legacy `.doc` documents. An available local LibreOffice engine converts legacy Word files with tables, images and formatting. Legacy documents and DOCX files with floating objects open in **Page view**, a compatible Office-rendered reading view that also supplies unchanged-document printing and PDF export. Fit page, Fit width and fixed zoom choices make reading convenient. This view can differ from Word or Google Docs on complex formatting. **Edit document** keeps editing available; after edits, printing uses the current editor contents. If the conversion engine is unavailable, legacy text recovery shows a persistent notice explaining the formatting loss.

Save retains the original `.doc` or `.docx` format. An unchanged document is saved byte-for-byte, while an edited `.doc` is converted to a real Word 97–2003 file. Save as and Word export create DOCX copies. Before replacing an edited complex source, Simple keeps its first original beside it as `name.before-simple-edit.doc` (or `.docx`); an external-file hash check blocks overwriting changes made by another application. Existing recovery support remains available.

The editor and its PDF exporter use installed Windows font faces and their actual vertical metrics when supported, with bundled fallbacks otherwise. A reproducible adapter to the pinned WordCanvas version prevents behind-text header watermarks from reserving body space, preserves centered anchors/luminance on DOCX export and keeps backgrounds behind readable text. Repeated print/PDF exports reuse a cached render until the document model or review changes. Office conversions share an in-memory content-hash cache bounded to eight results / 64 MB and a validated per-user disk cache bounded to 128 results / 256 MB. The optional engine is discovered from `SIMPLE_LIBREOFFICE_PATH`, the per-user `simple/office-runtime` folder, a companion `tools/libreoffice` folder or a normal LibreOffice installation; each conversion has a separate profile and a timeout. Cached legacy DATE/TIME results are locked in temporary conversion copies so viewing and printing do not silently replace a historical date with today; original files remain unchanged.

Printing opens an in-app two-pane setup: controls on the left and the actual composed, paginated PDF on the right. It supports the Windows default or a named printer, copies, color, duplex, collating, all pages or validated ranges, document/Letter/A4/Legal/A5/Tabloid paper, portrait or landscape orientation, margin presets and custom margins, fit/actual/custom scaling, centering, an optional document-title header, and optional page numbering. “Document size” preserves every selected page’s own size and orientation, including mixed documents. The vector PDF shown in the preview is the same payload sent silently to the selected printer; no second system dialog opens, and existing document colors, images, headers, and footers remain intact. Electron and Windows expose only one native paper choice per print job, so mixed-size document jobs use the printer’s default paper and may be fitted by the driver; the in-app preview and composed PDF still preserve every page exactly.

## Development

- `npm run dev` starts the Vite renderer and Electron shell.
- `npm run typecheck` validates the renderer types.
- `npm test` runs type and print-layout regression coverage.
- `npm run test:print:ui` opens the multi-page fixture and verifies the split live-preview workflow over Electron.
- `npm run test:fidelity` checks real opening, byte-preserving Save, original-layout rendering and repeated print preview. `SIMPLE_DOCS_QA_INPUT` selects a private test source; `SIMPLE_DOCS_QA_EDIT=1` also checks edited DOC saving, its original backup and an external-change conflict, using temporary copies only.
- `npm run test:editor:stress` creates a synthetic six-page document through the actual Electron editor, fills two tables, uses lists, mixed scripts/fonts, a landscape section, wrapped image and footnote, and checks DOCX save/reopen plus PDF/HTML/Markdown/text exports. Run `npm run build:web` first. Artifacts stay in ignored `tmp/editor-stress`; native file pickers are stubbed only in the test host.
- `npm run build` creates the single-file portable Windows executable.

The editor engine is `@forevka/wordcanvas`, used under its MIT license.

Creation and export now retain square image wrapping and manual line breaks. Newly inserted tables place the caret in the first cell; notes beside wrapped pictures stay in PDF output. Web and Markdown exports embed local images, and all text exports retain section header variants and footnotes/endnotes. Installed Malgun Gothic supplements the bundled CJK subset only for missing glyphs, using measured coverage for both canvas and PDF. No Windows fonts are redistributed. The detailed stress results and remaining authoring limits are in `RELIABILITY_NOTES.md`.
